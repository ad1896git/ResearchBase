## 2. Protected record and exact encoding proposal

No new canonical database schema. One immutable operator-protected local record
is approved per composition root; observations/hash/UID alone do not authorize it.
Proposed internal value `ProtectedBindingV1` has every listed field required.
No unknown keys, omitted values, generic JSON core, caller override or approved
boolean. Actual deployment values remain UNASSIGNED_OWNER_INPUT.

Top-level serialization is a fixed ordered JSON array, prefixed by the literal
ASCII bytes `researchbase.bearing.binding.v1` then one byte00. JSON: UTF8 without
BOM, compact separators comma/colon, no whitespace outside strings, no floats,
NaN/infinity, trailing data, comments or duplicate structure. Integers are decimal
no leading plus/zero except0, bool is not int. SHA256 lower-case64hex, OID
1..4294967295 (catalog zero sentinel fields below explicitly allow0), UID/device/
inode nonnegative bounded uint64, system_identifier canonical decimal text
1..18446744073709551615. No automatic Unicode/path normalization: human strings
must already NFC; path observations must preserve exact approved spelling.
Time is required UTC `YYYY-MM-DDTHH:MM:SS.ffffffZ`, no offsets/leap seconds;
comparison uses aware UTC and denies at equality. Strings cannot contain NUL or
surrogates; path/identity fields additionally reject control characters. Function
body/definition text may contain tab/newline encoded by JSON escapes; compare exact
text rather than normalize SQL. Maximum record64KiB, string body32KiB,32ACL entries,
32role-membership entries,16catalog config entries; excess denies, never truncates.
These bounds are conservative proposed review choices, not installation inventory
limits or resource budgets, and may require adjustment from real accepted source.

Fixed array order (nested arrays have order below):

| Position | Name/type |
| --- | --- |
| 0 | version integer1 |
| 1–4 | deployment_id/provenance/namespace/host: bounded NFC text (1..1024 UTF8bytes each) |
| 5–6 | uid:uint64; expires_at:UTC text |
| 7–8 | installation_manifest_sha256; installation_artifact_sha256 |
| 9–11 | fixed_callable_module/qualname; code_sha256 |
| 12 | composition_root_id: operator-assigned bounded text; no caller-selected root |
| 13 | topology literal SINGLE_HOST_LOCAL_FS |
| 14 | database: DatabaseBinding tuple |
| 15 | enabled_function: EnabledFunctionCatalog tuple |
| 16 | cas: LocalDirectoryIdentity tuple |
| 17 | lease: LocalLeaseIdentity tuple |

DatabaseBinding order: system_identifier(decimal text), server_version_num(int,
180000..189999), transport(UNIX or LOOPBACK_TCP), server_address(text|null),
server_port(int|null), database_name(text), database_oid(OID), database_owner_oid
(OID), alembic_revision(text), session_role(RoleIdentity), current_role(RoleIdentity).
UNIX requires both address/port null, matching PostgreSQL inet-server observations;
LOOPBACK_TCP requires canonical numeric loopback address and1..65535 port, no DNS
lookup. IPv4/IPv6 canonicalization algorithm must be selected in review, not assumed
from display text. Arbitrary remote DB, network FS and multi-host topology deny.
No unverified local test-cluster values are copied into an approved record.
RoleIdentity order: oid,name,superuser,inherit,createrole,createdb,canlogin,replication,
bypassrls, sorted_set_of_direct_membership_role_oids. Names/OIDs both match;
privilege flags are real bool. Ordinary reader/writer safety and restricted owner
role separation remain D1 gates; the record does not grant role membership.

LocalDirectoryIdentity order: absolute_path,namespace,device,inode,owner_uid,mode.
LocalLeaseIdentity order: absolute_path,device,inode,owner_uid,mode. Modes are actual
permission-bit integers, proposed directory0700/lease0600; require protected parent
chain, no symlinks, stable singly-linked regular lease inode and local reliable
locking. Existing lease check alone does not prove topology or approved ownership;
protected operator provisioning plus actual observations are required. OS/filesystem
support proof remains a prerequisite; guessing local from path spelling denies.

## 3. Closed typed PostgreSQL catalog observation proposal

Neutral frozen dataclasses live in foundation and contain no engine/session/SQL/
persistence objects. Persistence implements `BindingPreflightPort.observe()` using
an explicitly composed fixed connection factory, never a caller URL. One read-only
snapshot reads cluster identity, endpoint, DB identity, authenticated roles, one
Alembic head and exact `public.pr316d1_enabled()` catalog. Missing permissions,
ambiguous/missing head, non18 version, unsupported column inventory or mismatch
raises typed preflight denial, not fallback/automatic privilege grant.

Required EnabledFunctionCatalog positions are fixed in this order:
`oid,proname,pronamespace,proowner,prolang,procost,prorows,provariadic,prosupport,
prokind,prosecdef,proleakproof,proisstrict,proretset,provolatile,proparallel,
pronargs,pronargdefaults,prorettype,proargtypes,proallargtypes,proargmodes,
proargnames,proargdefaults,protrftypes,prosrc,probin,prosqlbody,proconfig,proacl,
identity_arguments,result_signature,definition`.

OID fields are bounded integers (provariadic/prosupport may be0); nargs/defaults
nonnegative integers; bool fields bool; kind/volatility/parallel exact one-character
closed enums checked against approved values; costs/row estimates canonical exact
nonnegative decimal **text**, never binary float. OID arrays preserve order;
nullable all-arg/mode/name/config/transform arrays retain null versus empty and
ordinal sequence. proargdefaults/prosqlbody are required nullable pg_node_tree
text observations, not executable input. Source/binary/definition and catalog
identity/result strings are exact UTF8 text with explicit null where PostgreSQL
permits it. proacl distinguishes SQL NULL from empty: required nullable ordered
ACL-text tuple plus a separately typed expanded ACL set must be frozen in review;
no conflation of default PUBLIC grants with no grants. ACL expanded item proposal:
(grantor_oid,grantee_oid,privilege,grantable), grantee0 means PUBLIC, sorted by tuple.
All attributes, source body and exact signature/result/definition must match the
operator-approved baseline; before-activation helper remains literal false. No
D01 read-only checker ever writes true or performs DDL.

**Unclosed catalog blocker:** verify this proposed PostgreSQL18 column/type/null
inventory against the accepted actual catalog query projection and freeze exact
ACL expanded/raw representation and decimal/node-tree textual codec. Current repo
`search_fixtures.catalog_snapshot` is deliberately smaller (regprocedure/functiondef/
ACL only), so it cannot by itself supply “all attributes” proof. No DB was queried
here. Literal valid/negative byte vectors, including UNIX null endpoint, role/OID
substitution, ACL NULL-vs-empty and body text, must be independently checked before
this proposal can be frozen. They are NOT YET COMPUTED, not PASS.

## 4. Public installation-proof seam proposal

Proposed new foundation public signatures, not existing code:

```python
@dataclass(frozen=True, slots=True)
class InstallationBindingExpectation:
    deployment_id: str
    manifest_sha256: str
    artifact_sha256: str
    callable_module: str
    callable_qualname: str
    callable_code_sha256: str

class VerifiedInstallation:
    def consume_for_binding(
        self, *, expected: InstallationBindingExpectation,
        fixed_callable: types.FunctionType,
    ) -> InstallationBindingWitness: ...
```

Witness is opaque, module-issued, exact-type, PID+code-object+approval/manifest
bound, noncopyable/nonpickleable, no public constructor or truth/approved flag.
Implementation must retain the real original protected approval/manifest identities,
expiry, prepared/finalized import closure and callable object internally; current
private slots are insufficient. Module owner may expand its internals in later
implementation; external consumers may not read/mangle private attributes.
Public consumption validates original proof issuance, same process, fixed actual
`researchbase.agent_runtime.domain.bearing_evaluation.evaluate` object/code identity,
expected material and unexpired protected approval, then atomically consumes once.
Wrong expectation/callable, repeated consume, mutation, fork, expiry or substitution
deny. No caller supplied verifier, loader or authority source is accepted. A hash
is an expectation to match the original proof, not new operator authorization.

The subsequent `verify_binding(...)` proposal consumes the witness only once,
compares approved record+fixed typed DB observation+actual CAS/lease identity and
returns only an opaque BindingPreflightProof bound to PID/root/record digest/
installation/lease. Failed construction poisons that witness and cleans up the
same owned lease; caller must repeat protected startup, never silently retry a
consumed proof. This is an intentionally conservative proposal requiring review
for retry/diagnostic usability. No public path recreates/copies the proof.

Foundation does no DB I/O and imports no Application/ORM/psycopg; DB preflight port
is called by protected operator composition outside scientific transactions.
Application sees only future typed non-I/O identity guard. Check proof before any
use; no serialized transfer or generation-derived entitlement. D03 must freeze
actual commit/revoke lifetime; D01 proof does not register a consumer or authorize
scientific write. Existing CLI/API roots remain default-deny.
