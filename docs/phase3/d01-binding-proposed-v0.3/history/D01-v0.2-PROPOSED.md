# D01 exact binding candidate v0.2 — PROPOSED, not owner architecture freeze

This increment preserves v0.1 and its evidence. It supplies a deterministic offline
codec specimen, 42 literal positive/negative byte vectors and concrete catalog/ACL/
role/address/signature choices for independent review. It is not a production
verifier, implementation authorization, actual DB observation or deployment record.
All values in vectors are synthetic; no real host/role/credential is selected.

## 1. Encoding closed for this review candidate

The v0.1 top-level 18-position array and domain prefix remain. The exact prefix is
ASCII `researchbase.bearing.binding.v1` plus00, hex is in vectors.json. UTF8 JSON
array is compact, ensure_ascii=false, no BOM/trailing data/floats/nonfinite values;
re-encoding must reproduce every input byte. Thus whitespace and Unicode-escape
aliases, even if JSON-equivalent, deny. Strings must already NFC; no normalization
of approved record material. Names/path/callable constraints and literal limits
are specified by generate_vectors.py and schema below. That script is an isolated
review specimen in this control directory, not ResearchBase source or a runtime
installation helper. Only its `main` writes these new local vector artifacts.

`literal-bytes/*.bin` contains actual exact bytes, including domain00 and malformed
UTF8/over-limit negative cases. vectors.json records UTF8 representation, full hex,
length, SHA256, fixed synthetic decision time, expected outcome and contextual
expected binding SHA when applicable. Do not hash the JSON string escape rendering
instead of the `.bin` file. Vector `.bin` files themselves are never executable.

Positions0–13/16–17 retain v0.1 meanings, subject to exact limits below. Callable
is exactly `researchbase.agent_runtime.domain.bearing_evaluation.evaluate`, not
`evaluate_bytes`. Position14 DatabaseBinding now has exactly11 fields:

`[system_identifier,server_version_num,transport,server_address,server_port,
database_name,database_oid,database_owner_oid,alembic_revision,RoleGraph,
connection_profile_sha256]`.

The last hash binds the approved non-secret fixed connection profile. It does
not replace the actual factory identity binding in section5. No secret, password,
URL credential or credential dump is in record/vector material.

Procedure defaults, source body, node-tree text, flags and allother attributes must
match the actual independently approved baseline. A codec-valid record with a
changed helper body is still denied by comparison to the original protected
record. The specimen decoder's optional `expected` argument only demonstrates
this comparison in vectors; a future real binding verifier MUST always consume
and compare the original protected approval, never treat absent expected as trust.

ACL exact form is `[raw_kind,raw_items,effective_grants]`. raw_kind NULL requires
raw_items=null; raw_kind ARRAY requires ordered raw aclitem-text tuple (including
empty). Raw text is obtained by ordered unnest with ordinality; preserve catalog
order and role spelling. effective_grants is the sorted unique tuple set from
`aclexplode(COALESCE(proacl,acldefault('f',proowner)))`, each element
`[grantor_oid,grantee_oid,'EXECUTE',is_grantable]`; PUBLIC grantee is0. Empty explicit
ACL yields empty effective set; default NULL expands default function ACL. Thus
NULL versus `{}` never collapses, even when some effective permissions coincide.
Names are not accepted instead of grantor/grantee OIDs. Duplicate/wrongly sorted
entries, unknown privilege or excess count denies. NULL defaults remain a safety
observation, not a grant or permission to install anything.

## 3. Role graph and endpoint closure

This resolves reviewer concern that direct-membership OIDs omit option changes.
RoleGraph is `[session_role_oid,current_role_oid,role_rows,membership_edges]`.
Role row is `[oid,name,rolsuper,rolinherit,rolcreaterole,rolcreatedb,rolcanlogin,
rolreplication,rolbypassrls]`. Each exact pg_auth_members edge is
`[roleid,member,grantor,admin_option,inherit_option,set_option]`; native bool required.
Rows sorted byOID; edges sorted by their entire tuple with no duplicates.

The adapter reads one REPEATABLE READ READ ONLY snapshot and obtains complete
membership ancestry C of session/current user, including edges regardless of
option. E is EVERY membership row whose member is in C. R contains C plus both
DB/function owners and every edge grantor. Fetch complete role rows R and E or
fail; do not silently LIMIT/truncate a partial graph. Limits128roles/256edges are
checked by over-limit sentinels/counts, not “first N means complete”. A missing,
changed or newly relevant edge/options/role row changes the approved typed record.

The first consumer-writer profile conservatively refuses ANY ancestor route to
DB owner or helper owner, even if current set/inherit flags are false, and refuses
reachable elevated-role flags or ADMIN edges. Thus it does not accidentally allow
an indirect SET route. Explicit SET/inheritance reachability can additionally be
computed from set_option/inherit_option+rolinherit for diagnostics, but cannot
weaken that conservative deny. This is a proposed restriction of supported first
profiles, not a claim that SQLNULL or rolinherit alone determines PostgreSQL
privilege. Real object/schema ACL/ownership/writer privileges and effective grants
remain additional D1 safety observations/review gates; this graph is NOT a complete
DDL-privilege attestation or a substitute for restricted-role provisioning.

Transport is a closed proposal: UNIX requires observed inet_server_addr and
inet_server_port BOTH null. The protected non-secret connection profile still
binds requested socket-directory/configured socket port; null actual inet values
must not erase that route. LOOPBACK_TCP requires numeric loopback IPv4 orIPv6;
record address must exactly equal Python3.12 `str(ipaddress.ip_address(text))`.
Adapter canonicalizes the actual numeric inet text through that fixed pure method
before comparison; parser rejects noncanonical record spellings. No DNS, zone ID,
IPv4-mapped IPv6, remote/multihost or null/nonnull mixing. Values127/8 and::1 are
loopback only, not an actual chosen approved endpoint. Both protocol versions have
positive specimens; alias/remote/mapped negatives reject. P03 remains a separate
unassigned dedicated Linux environment direction; this D01 transport does not
create a scientific execution sandbox on the Mac.

## 4. Exact limits and error surface proposal

All limits are codec/inspection guard ceilings, not scientific resource profile,
pricing, owner compute budget or granted runtime duration. They are fixed by the
reviewed codec version, not caller overrides. Aggregate record limit dominates
individual field limits; not every per-field maximum is simultaneously encodable.

- Encoded record including prefix ≤65536bytes. Identity text ≤1024 UTF8bytes;
  PostgreSQL role/DB names ≤63bytes. Hash exactly64lowerhex.
- Function source/default/node-tree/binary text ≤8192bytes each; definition ≤16384.
  Body strings permit tab/LF/CR; identity/path strings reject allcontrol chars.
- OID32positive unless explicit0 sentinel; UID/dev/inode uint64; version exactly1,
  PG server_version_num180000..189999, systemID decimal string in1..2^64−1.
- Roles128, membership edges256, raw ACL entries32, effective grants64,
  config entries16×2048bytes, argument/transform/name arrays128 entries.
- Paths exact absolute lexical strings≤4096bytes; no trailing slash, `//`, dot or
  dotdot components. Later filesystem observation must reject symlink/changed
  realpath/ownership/modes/inodes; lexical codec alone does not prove local FS.
- UTC required six fractional digits with Z; valid calendar only, at<expires_at;
  equality denies. Actual trusted preflight clock/TOCTOU/fork checks are separate
  future implementation concerns, not supplied by caller `at` as in offline vectors.
- Synthetic vectors and schema use CAS0700/lease0600, same approved UID. Actual
  provisioned ownership/namespace protection and reliable local lease remain required.

The specimen uses closed denial tags only for reproducible offline vector checking.
They are NOT new public ErrorCode values. Future D02 should expose a neutral
`BindingPreflightError(reason: closed literal, cause omitted/redacted)` internally,
with approved Application-facing mapping reviewed separately; no SQL diagnostics,
credential values or full record secrets in user errors. Missing permissions is
explicit denial, never auto GRANT, fallback query or a presumed match.

## 5. Public proof/factory identity proposal (no private-field consumer)

D01-v0.1's public `VerifiedInstallation.consume_for_binding(expected=...,
fixed_callable=...)` remains the proposed module-owned one-time seam. It must
retain original protected approval/manifest/root/code/PID/expiry internally; its
current measurements-only object cannot prove those expectations. Consumers must
not read mangled/private fields. Source implementation is NOT authorized here.

Additionally freeze these neutral protocol signatures for independent review:

```python
class FactoryIdentity:  # opaque, module-issued; no constructor/copy/serialization
    ...
class OperatorRootContext:  # opaque, fixed protected composition, same PID
    @property
    def factory_identity(self) -> FactoryIdentity: ...
class BindingPreflightPort(Protocol):
    @property
    def factory_identity(self) -> FactoryIdentity: ...
    def observe(self) -> DatabaseObservation: ...
class BindingPreflightProof:  # opaque, one root/installation/record/lease
    def assert_factory(self, *, identity: FactoryIdentity) -> None: ...
```

The fixed protected composition constructs the actual readonly observation port
and future actual UoW factory from the SAME approved connection-creation root,
retaining the actual factory/pool objects privately in trusted composition. It
issues one opaque FactoryIdentity only after protected startup/source verification;
no user constructor, caller boolean, raw URL or matching string rootID can issue it.
The observation port and wrapper around the actual future UoW factory carry that
SAME identity object; wrapper code captures its actual creation function/pool and
must check identity+fixed callable/code object before creating any session. An
arbitrary second factory cannot acquire authority by copying public observed DB
values or a record's composition_root_id. Identity equality means object identity
with captured live root/factory linkage, not equality of fields or digest strings.

The foundation proof compares these original issued objects through public seams;
no ORM/SQL/factory internals cross into foundation/Application domains. Genuine
registration must retain exactly the verified wrapper and refuse any caller-
supplied substitute. The later D03 path must trace this wrapper to actual UoW
commit under the lease/commit guard, including after reconnect/pool replacement;
matching preflight facts alone are insufficient. Pool/factory/code replacement
revokes rather than reuses the token. This is a concrete required identity seam,
not a claim that existing factories are linked or any generic registry is added.

FactoryIdentity issuance/validation belongs to the fixed protected composition
and its verified code inventory, not untrusted plugin adapters. Exact construction
location and tests must be frozen with D02/D03 and cannot be inferred merely from
these Protocol method names. It remains an IMPLEMENTATION GATE, while this review
can settle the required public signature and same-object/captured-factory rules.

## 6. What is technical proposal versus owner selection

Routine candidate choices for independent technical review: unique byte grammar,
field order/types, all30 pg_proc projection, float4 binary codec, ACL distinction,
role-edge option inventory, IP codec, per-field guard ceilings, opaque public
signature and failure categories. None changes a scientific invariant or creates
an installed service. An independent finding can refine them before any freeze.

Still requires explicit owner/operator selection or approval before use: actual
host/UID/deployment/DB/roles/endpoints/socket/CAS/lease values and filesystem
support; permission grants or supported topology expansion; any desire to allow
owner ancestry/current elevated roles; installing/activating/registering/writing;
thread/concurrency model expansion beyond current local lease contract; real
resource/billing/production profiles. No values/credentials or budget are invented.

The conservative writer graph rule may require different provisioning for a real
operator using inert owner memberships. Such a case must be reported explicitly
for owner/operator review, not worked around by ignoring options/graph edges.
No migration, lifecycle transition, public ErrorCode, source implementation or
architecture/ADR acceptance follows from passing the offline codec vectors.
