## Per-caller trace

**RESOLVED — common prefix.** Human and Agent commands each use one synchronous READ COMMITTED task transaction. First Application SQL is exactly the sorted 18-table SHARE in `docs/proposals/PR3-16_Search_Lineage_Contract_DRAFT.md:215` through `:226`; no preliminary authentication or receipt SELECT, SET LOCAL, advisory lock, write or autoflush. Then acquire `rb_phase2_lock_project(project_id)`, `pr301:command:<project_uuid>:<authenticated_actor_uuid>:<command_uuid>`, and `pr301:task:<task_uuid>`, in that order. Invoke fresh validation after each blocking stage, including the SHARE. For a verified Agent caller, the proposed trace takes `pr302:actor:<authenticated_actor_uuid>` and invokes fresh validation immediately afterward; it takes no version or execution key. Both then continue to the common rows below. Question: does architecture review approve this actor-only key selection and the absence of an actor row lock for each caller? Options: (1) approve this proposed Human/Agent split; (2) specify a different existing identity coordination and its position before task rows, with mixed-writer evidence. Recommendation: option 1 for review, not an established freeze: the actor key exists in the version writer (`src/researchbase/persistence/agent_version_repository.py:77`); that writer also locks actor rows (`src/researchbase/persistence/agent_version_repository.py:81`), so it does not itself establish the search recipe. **RESOLVED — validation and effects.** After every wait, including row, FK and constraint waits, authenticate and check current read entitlement, then inspect the committed project/actor/command receipt. Equal hash returns original IDs before write authority, state or CAS; unequal hash conflicts. With no committed receipt, refresh write authority and all applicable admission predicates before effects. After each DML and constraint forcing, refresh entitlement, committed replay and fresh admission; exclude this transaction's own uncommitted receipt from replay. Update the task once, insert one receipt, one search event, one task event and one receipt-event link, plus one session for create or one node for append. Both commands have zero Run-link effects. Force deferred constraints while holding locks, then commit once; failure rolls back.
