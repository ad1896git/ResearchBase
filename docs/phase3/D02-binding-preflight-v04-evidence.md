# D02 v0.4 development binding preflight

This is a bounded development implementation, not whole-D02 completion or a
genuine reference/production registration. D01 v0.4 is its frozen input. The
separately authorized local facility uses existing local trust; it is not A2 or a
protected reference authentication proof. No scientific write, helper enablement,
Application wiring, runtime activation, migration version or dependency is added.

The sole engine creator retains ordinary engine/session/UoW/HG1/Alembic behavior.
Its new protected development factory consumes a genuine one-use installation
witness, reads a protected binding record, verifies CAS and a real local lease,
and compares the actual PG18 identity, roles, head, helper and complete normalized
ACL in one repeatable-read read-only snapshot. Direct/indirect elevated/owner
memberships, reachable DDL/DML privileges and object ownership deny. No supplied
URL, observation callback or boolean can issue a proof.

The private NullPool root retains one SQLAlchemy Connection and actual driver
for its entire lifetime. New observations replace old ones; the non-I/O identity
port checks the original PID/thread/wrapper/code/root and pin. Root-continuity loss,
replacement, invalidation, overlapping sessions or failed preflight quarantine the
root. Cleanup attempts every owned resource and retains failures. Unconfirmed
cleanup keeps the lease held; test-only disposal after injected faults does not
reactivate the root. `close_checked` proves only an owned local descriptor close,
not DB rollback, D03 REVOKED or a write permit. Actual bound-write adoption remains
**NOT_IMPLEMENTED** for D03/D06.

## Supported development runtime and preserved failures

The original import-origin verifier rejects native extensions' unobservable
`cython_runtime` module. It remains rejected. This development profile therefore
uses the same locked dependencies with `DISABLE_SQLALCHEMY_CEXT_RUNTIME=1` and
`PSYCOPG_IMPL=python`, supplied by the protected test launcher before imports.
There is no automatic fallback or verifier exemption. The explicit test PATH
selects the already authorized Homebrew PG18 `pg_config` to locate libpq; no SQL
is executed by that metadata utility. Ordinary factories retain their defaults.
This is development runtime evidence, not approval of a genuine native/reference
installation or its external native-library closure.

All failed drafts are preserved: the first native-origin denial, missing libpq
lookup with an intentionally stripped PATH, and a prematurely started repeat
interrupted after 9.25s with no completed case. That scheduling error was reported
and stopped; later PG runs are sequential. A `/dev/null` passfile deliberately
prevents credential-file consumption and produces libpq's non-regular-file
warning; existing local-trust authentication is disclosed, not upgraded to A2.
The fork-negative case may emit Python's multi-threaded-fork warning; the child
only checks PID denial and exits without DB work.

No remote publication, owner label, merge, registry, production service or DB
administration is part of this evidence. HIGH risk and the normal independent
review/seven-check/owner merge gates remain.
