# M3 local literature evidence workflow

Use the existing Local-First installation and authenticated project membership. Each write requires a fresh `--request-id UUID` before the command group. No actor override or automatic approval is available.

1. Import a lawfully retained local UTF-8 text or JATS XML file with `literature-evidence import-document --project-id PROJECT --path FILE --media-type application/jats+xml --rights-basis "Attribution, license/permission and local retention basis" --json`. The result identifies the immutable ArtifactVersion and its SHA-256 digest. The supplied basis records the user's assertion; it does not itself grant rights. Access policy is PROJECT_LOCAL.
2. Reuse `literature version create` for an existing LiteratureSource with `--material-json` containing `version_kind`, `title`, `authors` and `fulltext_artifact: {"id": "ARTIFACT_VERSION", "content_hash": "SHA256"}`. Freeze that new SourceVersion with `literature version freeze`. Preserve earlier frozen versions.
3. Inspect exact content using `literature-evidence inspect --project-id PROJECT --source-version-id VERSION --paragraph N --json`.
4. Select an exact bounded passage using `literature-evidence create --project-id PROJECT --source-version-id VERSION --artifact-version-id ARTIFACT_VERSION --quotation "Exact text" --paragraph N --start START --end END --json`. Paragraphs are one-based; offsets are zero-based Unicode codepoints, end exclusive. Omit the three selection arguments only for a unique exact match. Repeated matches require explicit selection. Evidence begins UNREVIEWED with deterministic RULE extraction and MODERATE confidence.
5. Read back with `literature-evidence get --project-id PROJECT --evidence-id EVIDENCE --json`. The service verifies original bytes, source hash, literal evidence hash and relocation before returning content.
6. An authorized independent authenticated HUMAN can issue `literature-evidence review --project-id PROJECT --evidence-id EVIDENCE --status VERIFIED --basis "Exact passage inspected and explicit assessment" --json`. DISPUTED and REJECTED are explicit assessments too. Review events are append-only; verification never rewrites quotation/hash. The implementation cannot prove that a person actually read a passage: real acceptance requires witnessed inspection and explicit verification.
7. Create a support snapshot with `literature-evidence support-create --project-id PROJECT --target-type HypothesisVersion --target-version-id FROZEN_VERSION --inputs-json '[{"evidence_id":"EVIDENCE","relation_type":"CONTEXTUALIZES","qualification":"Why the passage provides context"}]' --json`. ClaimVersion and ResearchQuestionVersion are also concrete targets. Read via `literature-evidence support-get --project-id PROJECT --snapshot-id SNAPSHOT --json`. Existing `local hypothesis-create` / `local hypothesis-freeze` expose the authenticated Application path for demonstration targets.

SUPPORTS additionally requires the latest review event to be VERIFIED by a HUMAN distinct from both extraction actor and snapshot author, valid source content, and a valid frozen target. Other approved relations are CONTRADICTS, QUALIFIES, MOTIVATES, PRIOR_ART and CONTEXTUALIZES; RELATED is rejected. Each edge requires an explicit relevance/disagreement basis. Duplicate/conflicting edges for one evidence record are rejected. A successor snapshot replaces the complete relation set; an empty set is an explicit removal. It never changes Phase 1 Claim/Hypothesis hashes or experimental EvidenceRelation ownership.

Source retraction/correction, later dispute or rejection, and Claim governance validity affect the current read projection without mutating scientific history. Missing or altered original artifacts fail closed. Replays reauthorize current credentials and check current canonical content; a replay can return later review/validity state rather than a stale cached response. An interrupted document transaction may leave an unreferenced content-addressed blob; it creates no canonical scientific record.

Supported slice: files up to 8 MiB; exact quotations up to 2,000 characters; strict UTF-8 text and bounded JATS XML without entity declarations. PDF/OCR, model paraphrases and crawlers are outside M3. Text paragraphs split on blank lines. JATS paragraphs are all `p` elements in document order with `itertext()` concatenation, including front/back matter; parser identity is manual-document-v1. Retain original bytes for reproducibility.

The approved production authentication profile remains single-user. No separate authenticated reviewer has been designated; independent human acceptance is NOT RUN. Distinct test actors exercise the technical mechanisms only. See the completion report for the M3_PARTIAL acceptance boundary and exact evidence.
