# Phase 2 Schema Field Contract v1.0

**Status:** normative companion to Final Correction Addendum A17 and Phase 2 Architecture and Contract Correction v1.0. It is design only. No migration or Phase 2 implementation is authorized.  
**Precedence:** Final Correction Addendum A17 → Global Registry → this field contract → Phase 2 specification for fields not contradicted here. If a field below differs from older Phase 2 prose, this contract governs because A17 incorporates it.

## Shared physical rules

Unless stated otherwise every table has `id UUID PRIMARY KEY`, `created_at TIMESTAMPTZ NOT NULL`, `created_by UUID NOT NULL REFERENCES actors(id) ON DELETE RESTRICT`; row versions on mutable identity/operational tables are positive integers. Exact material/version FKs use `ON DELETE RESTRICT`; no scientific table has a delete cascade. The service validates actor/project authorization and exact target state in one transaction. PostgreSQL constraints/triggers independently enforce XOR, same-parent, frozen immutability and unique keys. A `content_hash CHAR(64)` row also has `hash_scheme VARCHAR(32)` constrained to `sha256-cjson-v1`; `support_set_hash`, `placement_set_hash`, `basis_set_hash`, and `package_manifest_hash` are separate 64-character lowercase hexadecimal bindings using the same scheme. Nullable hashes are permitted only in DRAFT/PREPARED state; FROZEN requires all applicable hashes and `frozen_at`. Immutable records require own hash at insert.

The column lists below are exhaustive for scientific/business semantics; standard `id/created_at/created_by/row_version/hash_scheme` columns follow this shared rule. `JSONB` is allowed only for named, schema-validated structured fields (`locator`, `scope`, `criteria`, `conditions`, `metadata`, `manifest`, `external_context`); it is never a generic formal reference list or canonical polymorphic target. All canonical ID collections are typed relation rows. `status` and `kind` columns have uppercase CHECK values. Every FK column has a B-tree index unless its leading columns are covered by a stated unique index. Large text values have application limits documented by their command DTO; database `NOT NULL` and nonblank checks apply to required statements.

## Organization and identity — migration 0019

The exhaustive `0019` columns and constraints are in correction §7.1. `project_membership_events` has `id, membership_id, prior_status, new_status, actor_id, occurred_at, reason`; `project_role_events` has `id, role_assignment_id, actor_id, event_kind, occurred_at, reason`. Both have PK, parent/actor FKs RESTRICT, status/event CHECK, and `(parent_id,occurred_at,id)` indexes. They are immutable. No Phase 1 table is altered. Initial OWNER assignment and bootstrap are one serializable Application transaction.

## Literature identity — migration 0020

The exhaustive `literature_sources`, `source_identifiers` and `source_identifier_verification_events` columns and constraints are in PR2-01 execution pack §Schema. PR2-02 source lineage adds `source_merge_records` with `id UUID PK`, concrete losing/winning source FKs, frozen `identity_basis_artifact_version_id` FK, `reason`, `merged_by`, `merged_at`, `content_hash` and `hash_scheme`; losing and winning IDs must differ, losing source is unique, and UPDATE/DELETE is forbidden. That migration also adds source MERGED status and `merged_into_source_id` self-FK with acyclic root enforcement. `current_version_id` is added with `source_versions` in PR2-02, with same-parent composite FK.

## Migration verification

Each authorized PR adds only its tables/constraints and a single linear Alembic revision. PostgreSQL 18.x tests cover fresh DB→head, frozen Phase 1 `0018`→head, invalid legacy state fail-closed preflight, constraints under concurrency, frozen-state UPDATE/DELETE rejection and a data-preserving downgrade refusal. For PR2-00, the exact legacy-state predicate and no-rewrite behavior are defined by Addendum A22 `LEGACY-STATE-01`. No migration rewrites Phase 1 canonical rows. Exact column/index names may use the repository's established naming convention, but their semantics, types, keys and checks above are fixed; a semantic change requires ADR and revised contract before code.
