# ResearchBase TDG-2 — Phase 2 Technology Decision Gate v1.0

**Status:** ACCEPTED FOR DESIGN; implementation remains subject to Phase 2 reauthorization and each PR gate.  
**Authority:** Final Architecture Correction Addendum A13; System Architecture; Global Registry; Cross-Phase Contracts.  
**Scope:** Phase 2 literature retrieval, extraction, research strategies, and adapter boundaries. No adapter is enabled by this document.

## Decisions

| ID | Decision | Required contract |
|---|---|---|
| TDG2-01 | OpenAlex is the default live bibliographic search provider | `SearchCapability` accepts a frozen `LiteratureSearchPlanVersion`, typed provider selection, bounded query, and execution context. It returns candidates and provider provenance. It never creates SourceVersion or LiteratureEvidence. Phase 2 requires an OpenAlex adapter plus a deterministic test adapter; additional live providers are optional. OpenAlex's Works search/filter API is the selected default, subject to the adapter pin and access gate below. |
| TDG2-02 | Crossref is the default DOI metadata verifier | Crossref REST resolves DOI metadata; OpenAlex may provide discovery metadata, but neither response is authoritative without ResearchBase identifier verification. arXiv/PubMed/URL identifiers use ResearchBase-owned normalization and may receive later dedicated adapters. SourceResolver records provider name/version, retrieval time, and raw-response ArtifactVersion when retained. No provider ID is a canonical primary key. |
| TDG2-03 | Full-text extraction uses an optional GROBID sidecar | Prefer licensed/open-access source bytes captured as an immutable ArtifactVersion. When extraction is enabled, use a pinned GROBID REST sidecar behind a replaceable port; otherwise manually supplied verified locators remain supported. A locator must identify page/section/paragraph or stable source span. Extracted text is a candidate; copyright and access checks precede storage. Failure to obtain full text does not fabricate evidence. No GROBID-specific fields enter Core. |
| TDG2-04 | ScientificRAG/PaperQA2 is an adapter | ResearchBase owns the `ScientificRAGCapability` port and candidate/evidence promotion commands. PaperQA2 is a required Phase 2 adapter only after its exact version/commit, license, dependency lock, and security review are recorded in its PR. Serialized indexes from untrusted sources are never deserialized. Indexes and caches are derived and rebuildable. |
| TDG2-05 | Native STORM-like strategy is required | ResearchBase owns the strategy interface and native source-grounded algorithm. Official STORM is an optional thin comparison adapter pinned in its own PR. Neither STORM nor PaperQA2 owns canonical source, evidence, claim, conclusion, or manuscript state. |
| TDG2-06 | External I/O uses bounded execution steps | TX A records a `LiteratureSearchExecution`; external calls occur outside DB transactions; TX B appends query/results or failure; TX C transitions to terminal. Each call has timeout, cancellation, request correlation, idempotency key, and bounded retry. A timeout with uncertain provider outcome is recorded as `UNKNOWN`, not success. |
| TDG2-07 | Rate limits and retries | Respect `Retry-After`; otherwise exponential backoff with jitter and a configured maximum attempt count. `429`, transient `5xx`, and transport failures may retry. Validation/authentication failures do not retry. Exhaustion records terminal failure and preserves earlier query/result provenance. No implicit background queue is required. |
| TDG2-08 | Cache policy | Provider responses and RAG indexes may be cached outside canonical tables using provider, normalized request, adapter version and access-scope keys. Cache hits carry original retrieval and cache-read times. TTL and invalidation are configuration, not scientific validity. Retraction/correction checks cannot be satisfied solely from a stale cache. Cache deletion cannot delete canonical provenance. |
| TDG2-09 | Credentials and security | Secrets come from deployment secret injection, never canonical rows, artifacts, logs, prompts, or adapter DTOs. Project access is deny-by-default. Egress destinations and source licenses are allowlisted per deployment. Untrusted metadata, PDFs and retrieved text are data, never instructions or executable configuration. Logs redact secrets and copyrighted full text. |
| TDG2-10 | Vendor lock-in boundary | Core persists ResearchBase IDs, exact source/version references, provider-neutral execution facts, and adapter/version provenance. Provider response shapes, prompt format, embeddings, vector indexes, and STORM/PaperQA internal state remain in adapters or immutable raw artifacts. Replacing a provider requires no canonical migration. |

## Activation gates

TDG2 accepts the technology *roles and boundaries*, not an unreviewed upstream binary. Each live adapter PR must record its exact upstream version or commit, transitive lock, license, security review, timeout/rate-limit configuration, compatibility tests, and failure evidence before enablement. If these checks fail, that adapter remains disabled; the Phase 2 scope and canonical contracts do not change.

Primary provider references reviewed for this decision: [OpenAlex Works search](https://help.openalex.org/api/searching/), [OpenAlex authentication and rate limits](https://help.openalex.org/api/authentication/), [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), [GROBID full-text REST operation](https://grobid.readthedocs.io/en/latest/Grobid-service/), [PaperQA2 project](https://github.com/Future-House/paper-qa), and [Stanford STORM project](https://github.com/stanford-oval/storm). Their live terms, versions and security state must be rechecked in the enabling adapter PR.
