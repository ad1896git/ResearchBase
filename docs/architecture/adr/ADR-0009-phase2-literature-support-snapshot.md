# ADR-0009: Phase 2 literature support snapshot outside frozen Phase 1 Claim hashes

- Status: Accepted as an architecture **design correction**, subject to independent Phase 2 reauthorization; no implementation is authorized.
- Context: Phase 1 ClaimVersion `support_set_hash` and `content_hash` are frozen over Phase 1 EvidenceRelation semantics. R1 proposed adding LiteratureEvidenceRelation to that binding, which would change an already frozen scientific contract. A new canonical schema needs explicit architecture review under the complexity budget.
- Decision: Introduce one bounded Phase 2 literature support snapshot pattern owned by literature: immutable `LiteratureSupportSnapshot` and its `LiteratureEvidenceRelation` rows. A snapshot binds exact, already frozen ClaimVersion, ResearchQuestionVersion or HypothesisVersion and exact verified LiteratureEvidence rows through a Phase 2 `literature_support_set_hash` and own `content_hash`. It is created after the target freezes. It never writes or reinterprets Phase 1 target material, Phase 1 EvidenceRelation or Phase 1 closure code. A later support set creates a new numbered snapshot, with an exact predecessor and preserved history. ScientificConclusionVersion may explicitly bind an exact ClaimVersion plus an exact matching literature snapshot, or directly bind LiteratureEvidence in its own support set. Publication citations remain separate presentation placements.
- Complexity justification: The existing Phase 1 Claim hash cannot represent new literature support without historical hash drift. A single immutable snapshot and relation pattern gives the new fact one owner, a concrete provenance path and a verifiable digest without a generic target locator or parallel Claim object. The new schema is limited to Phase 2 literature support. Its exact fields, constraints and lifecycle are in the R2 architecture correction; its literal hash payload is in the R2 hash contract.
- Consequences: Older ClaimVersion digests remain valid and are checked by the unchanged Phase 1 validator. Formal consumers opt into exact Phase 2 literature snapshots. Retraction and review changes affect derived validity and may trigger a new snapshot; neither rewrites historical bytes.
- Rejected alternatives: Extending ClaimVersion `support_set_hash`; adding literature rows to Phase 1 EvidenceRelation; storing support only as an unverified citation; generic `target_type/target_id` formal provenance; silently reading latest literature support as historical evidence.
- Upstream authority: System Architecture scientific invariants; Final Correction Addendum A18; Cross-Phase Phase 1 compatibility.
- Scope: Phase 2 design. Migration placement and implementation remain separately gated.
