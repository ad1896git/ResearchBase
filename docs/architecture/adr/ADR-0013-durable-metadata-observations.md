# ADR-0013 — M2 durable bibliographic metadata observations

Status: ACCEPTED by architecture owner, 2026-10-10, M2-AQ-001 continuation instruction. Scope: M2 only; supersedes PR2-04 raw-observation deferral for this path. Existing scientific hashes and M0/M1 rules remain unchanged.

## Decision and physical contract

Migration 0029 adds only `metadata_observations` and the already specified `search_result_resolutions`, both dependent append-only relations, with RESTRICT FKs and FK indexes. No aggregate root, LiteratureEvidence, merge, scientific support or authentication redesign.

`metadata_observations`: UUID PK; project_id/result_id required FKs; deployment_id text; invocation_id UUID; request_fingerprint CHAR(64); provider_id/provider_version/adapter_version text; endpoint text; request_started_at/observed_at TIMESTAMPTZ; observed_by actor FK; outcome MATCH/CONFLICT/AMBIGUOUS/UNRESOLVED/UNAVAILABLE; failure_code nullable text; http_status nullable INT; artifact_version_id nullable FK; source_id nullable FK; source_version_id nullable same-source composite FK; content_hash CHAR(64); hash_scheme fixed sha256-cjson-v1. Replay key UNIQUE(deployment_id,project_id,observed_by,invocation_id); fingerprint binds result ID/hash, normalized DOI, provider/adapter, endpoint identity and timeout. The normalized DOI plus fixed endpoint/mapping determines the exact singleton path. Same key/different fingerprint fails; new invocation appends.

CHECKs: nonblank bounded provider/deployment/endpoint; hex hashes; request time <= observation time; HTTP status 100..599; version implies source; source implies MATCH; artifact absent implies http_status absent and outcome UNAVAILABLE and failure_code TRANSPORT_TIMEOUT or TRANSPORT_UNKNOWN. A timeout after HTTP headers arrive retains status, partial-body digest and incomplete-body diagnostic as an artifact-backed ambiguous observation; only failure before any HTTP response can be response-less. Thus missing DOI is UNRESOLVED with retained local identity assessment, not unavailable; malformed/404/429/5xx responses retain exact available redacted response material. Retention failure raises without committing an observation. MATCH requires artifact and no failure. No provider JSON in SourceVersion.

`search_result_resolutions`: UUID PK; required result/source FKs; optional same-source frozen version FK; actor/time/basis required; content_hash/hash_scheme; unique result/source/version established linkage (NULLS NOT DISTINCT). The observation's optional source/version records the established resolution at that observation, not a mutable pointer. New verified metadata observations do not overwrite frozen versions. Different observations may share an established resolution.

DB triggers reject UPDATE/DELETE; INSERT validates result→query→execution→plan project closure, frozen/superseded plan, artifact FROZEN/SUPERSEDED in same project, source project link, and frozen/superseded same-source version. Result and upstream provenance already immutable. No redundant text-form plan/execution UUID links. Artifact CAS bytes are verified by Application before commit and on observation read; PostgreSQL cannot verify filesystem content.

## Transactions, dispatch and crash safety

1. Short SERIALIZABLE admission authorizes current principal/project, validates exact result provenance and checks replay. No network inside a DB transaction.
2. A per-invocation operational file lock under the configured CAS root serializes concurrent local resolver processes. Fsync an exclusive intent fingerprint before external I/O. Completed redacted response material and timing are atomically fsynced to the journal before DB writes. This is an operational dispatch journal, not canonical science or a second database. A crash with intent but no completed observation refuses redispatch; caller must use a distinct new invocation. It does not fabricate response-less evidence. Completed journal data can only replay the same fingerprint and preserves original times.
3. Put/verify immutable evidence bytes in CAS before TX B, including fsync of file data and the object directory/ancestor entries. Directory-sync failure propagates before any DB observation write. In a fresh SERIALIZABLE transaction reauthorize after project/authority locks, check replay again, insert a frozen Artifact/ArtifactVersion and observation atomically through repository ports. Response-less transport observations have no artifact. DB retries repeat only this transaction using the completed response, never the external request. A failed commit may leave unreferenced CAS bytes, which are harmless. An uncertain commit is recovered by the unique observation key and retained journal; no deletion/rewrite of history.
4. After the observation/evidence commit, resolution uses existing scoped identity/version commands with deterministic subrequest IDs, then appends an established resolution in a fresh transaction. The original MATCH observation remains immutable; source references in observation rows are optional and this first implementation leaves them null. Existing command receipts make interrupted resolution resumable; no destructive dedup or cross-project lookup. A registered but unverified identity collision is not automatically adopted. Canonical identifier verification uses the exact frozen observation artifact basis through its existing command; bibliographic verification never verifies scientific claims.

## Comparison and compatibility

DOI follows source-identifier-normalization-v1. Exact compatible normalized title plus DOI is sufficient MATCH; incompatible DOI/title is CONFLICT; absent/insufficient title is AMBIGUOUS; no DOI is UNRESOLVED; response-less transport is UNAVAILABLE. Byline/ORCID, publication identifier/date comparisons occur when both sides provide values; otherwise missing comparison is explicit. Conflicting observations never overwrite canonical source history.

New rows use own literal hashes over all immutable columns except own hash. Existing hashes, tables, migrations and receipts are unchanged. Upgrade from 0028 is additive; downgrade refuses nonempty new history. Local trusted account/config/CAS/DB backups must remain together. The journal is not an Agent runtime, queue or recovery framework. Legacy CLI groups stay fail-closed; only M2 composition is enabled. API activation is outside M2.

Observation observed_at/observed_by and resolution resolved_at/resolved_by are the creation timestamp/actor fields for these dependent relations; no duplicate created_at/created_by columns. Hash material is exactly the public immutable row columns excluding content_hash, with UUIDs as strings and times as UTC ISO-8601 strings. Explicit hash_scheme participates. The new relation hashes do not modify existing scientific digests.
