# ADR-0008: Phase 2 literature technology roles and adapter boundary

- Status: Accepted for **design**; no adapter is activated or approved for deployment by this ADR.
- Context: Phase 2 needs replaceable bibliographic search, DOI verification, optional full-text extraction and scientific retrieval while ResearchBase retains canonical identity and provenance. Final Correction Addendum A13 requires TDG-2 results to be recorded as ADRs.
- Decision: ResearchBase owns `SearchCapability`, `SourceResolver`, `FullTextExtractionCapability`, `ScientificRAGCapability` and the native, source-grounded STORM-like research strategy interfaces. OpenAlex Works is the default live bibliographic discovery provider; a deterministic in-process test adapter is required. Crossref REST is the default DOI metadata verifier. GROBID REST is an optional full-text extraction sidecar, never a required route to evidence. PaperQA2 is the required scientific-RAG adapter when its enabling PR passes its activation gate. Official STORM is an optional thin comparison adapter; the native STORM-like strategy remains required. Each provider is reached only through its adapter and returns candidates and provider provenance. ResearchBase Application commands alone create or verify LiteratureSource, SourceVersion, LiteratureSearchExecution, LiteratureEvidence, Claim and ScientificConclusion facts. Provider identifiers, indexes, embeddings, cached responses, prompts, extraction internals and workflow state never become canonical ResearchBase ownership.
- Operational policy: External calls occur outside PostgreSQL transactions. Executions retain bounded timeout, cancellation, correlation, idempotency, retry and `UNKNOWN` outcome semantics. Retry only 429/transient 5xx/transport errors with `Retry-After` or bounded exponential backoff; authentication/validation errors do not retry. Cache entries carry retrieval and read times and do not decide scientific validity. Secrets come from deployment injection and are excluded from canonical rows, artifacts and logs. Provider responses are untrusted data.
- Activation gate: This ADR records architectural choices only. The enabling adapter PR must identify an exact upstream package version or commit, transitive lock, license/access terms, security review, credential and egress configuration, timeout/rate-limit settings, compatibility fixtures and failure evidence. Until those checks pass, that adapter remains disabled. No live-provider call or upstream validation is claimed here.
- Consequences: Provider replacement does not require canonical schema migration. A provider outage may halt retrieval while stored frozen provenance remains readable. No queue, vector database or third-party agent framework is introduced into Core.
- Rejected alternatives: Provider IDs as ResearchBase primary keys; vendor result JSON as canonical scientific evidence; STORM/PaperQA-owned canonical state; mandatory GROBID for all evidence; unpinned enabled adapters; automatic promotion of candidate text.
- Upstream authority: Final Correction Addendum A13 and A18; TDG-2; System Architecture; Global Registry; Cross-Phase Contracts.
- Scope: Phase 2 design. Separate PR authorization and verification are required before implementation.
