Root cause: test_execution_insert_phantom_both_lock_orders paused create() after
flushing the execution parent but before flushing its CREATED event. The waiting
assessment could SHARE-lock events before blocking on executions; the writer then
needed RowExclusive on events. PostgreSQL could abort/retry the writer, reversing
the commit order assumed by the assertion. The reproduced failure returned a valid
NoveltyReadback instead of the expected writer-first provenance denial, with a
CONCURRENT_MODIFICATION retry logged. This is a test synchronization flake.

Fix: pause save_receipt() after flushing the entire pending execution write set.
Assert RowExclusive locks on executions and execution events before releasing the
assessment thread, and assert that the held transaction was not retried. Keep the
observed database wait and both original scientific outcome assertions. No
production guard, transaction isolation, lock ordering, retry, or invariant changed.
