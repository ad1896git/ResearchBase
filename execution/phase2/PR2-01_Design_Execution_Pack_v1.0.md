## Goal and STOP boundary

Included: LiteratureSource and SourceIdentifier with typed commands/queries. Excluded: SourceMergeRecord implementation, SourceVersion, LiteratureSearchExecution, LiteratureEvidence, citation, conclusion, manuscript, external provider calls, Agent Runtime and any Phase 1 schema or semantic change. The later merge policy is defined here but not implemented in PR2-01. PR2-01 stops after independently reviewed source-identity evidence. It does not authorize PR2-02.

No scientific `ON DELETE CASCADE`. Existing Phase 1 tables are not changed. PR2-02 adds `current_version_id` with its concrete same-parent FK once `source_versions` exists. PR2-02 adds SourceMergeRecord and aliasing only after a verified human identity decision with an exact frozen basis ArtifactVersion; it preserves all frozen version parents and uses resolution aliases, never reparenting them. No merge occurs in PR2-01. SourceIdentifier verification changes only status/verification columns with an append-only verification event in the same transaction; its type, raw value, normalized value, owner and primary designation are immutable after creation. LiteratureSource identity contains public bibliographic metadata only; private local-corpus material stays in project-scoped ArtifactVersion. Every read/write requires an active membership in an explicitly supplied project and a source–project link. Registering a known public identifier from a second project adds that project's link in the same transaction without exposing other project associations.

`canonical_title` on LiteratureSource is immutable registration display metadata, never formal scientific content. Corrected titles belong to a new SourceVersion in PR2-02. A source identity created with a mistaken title remains historically visible; a correction/merge record or retired identity resolves identity errors without rewriting the registration row.

## Identifier rules

Normalize Unicode NFC, trim outer whitespace, reject controls and empty values, and cap stored normalized strings at 2048 code points. Type-specific rules are deterministic and versioned as `source-identifier-normalization-v1`:

| Type | Normalized form |
|---|---|
| DOI | Remove `doi:` and recognized `https://doi.org/` or `http://dx.doi.org/` prefix; percent-decode unreserved characters once; lowercase ASCII DOI suffix and prefix; require `10.` prefix, slash and nonempty suffix; preserve punctuation. |
| ARXIV | Remove `arXiv:` and recognized arxiv.org `/abs/` or `/pdf/` wrapper; strip terminal `.pdf`; lowercase archive prefix; strip explicit `vN` suffix into SourceVersion candidate metadata, so SourceIdentifier names the work identity; validate modern or legacy arXiv syntax. |
| PMID | Accept digits only; remove leading zeros by base-10 normalization; reject zero. |
| ISBN | Remove spaces/hyphens; uppercase `X`; validate ISBN-10 or ISBN-13 check digit; preserve digits/check digit. |
| URL | Require HTTP(S); lowercase scheme/IDNA hostname; remove default port and fragment; normalize unreserved percent encodings; preserve path/query ordering and case; reject username/password in URL. |
| SEMANTIC_SCHOLAR | Accept exactly 40 ASCII hexadecimal characters; lowercase them. Provider URL wrappers are rejected in PR2-01. |
| OPENALEX | Accept a Works ID `W` followed by a nonzero decimal integer, optionally wrapped as `https://openalex.org/W…`; uppercase the `W` and remove the wrapper. Other OpenAlex entity types are rejected. |
| OTHER | Require `namespace:value`, where namespace matches lowercase ASCII `[a-z0-9][a-z0-9._-]{1,63}` and value is 1–2048 NFC code points after outer trim; preserve value case. A namespace is registered in deployment configuration before use; unknown namespaces fail `IDENTIFIER_INVALID`. |

Normalization is pure and has table-driven test vectors. An UNVERIFIED or VERIFIED identifier value is unique; a REJECTED historical binding permits a new corrected row with the same normalized value. Identical title is never proof of identity. A different DOI is not auto-merged. Registration with an existing VERIFIED normalized identifier returns that canonical source only when caller input is compatible; an UNVERIFIED collision or conflicting source kind/title or explicit source target returns `SOURCE_IDENTITY_CONFLICT` for review. No provider response can auto-create an authoritative merge. Distinct verified identifiers may later be judged co-referent only by an authorized human decision with frozen identity-basis ArtifactVersion; the later merge command appends SourceMergeRecord, retains both source IDs and identifiers, rejects cycles, and never rewrites SourceVersion parents.

## Application surface and ports

Commands (one transaction each): `register_literature_source(context, project_id, kind, title, initial_identifier?, idempotency_key)`, `add_source_identifier(context, project_id, source_id, type, value, is_primary, idempotency_key)`, `verify_source_identifier(context, project_id, identifier_id, verification_basis_artifact_version_id, idempotency_key)`. Registration of an existing public source creates only the new source–project link. Verification requires a FROZEN ArtifactVersion documenting the identifier basis, an active Project OWNER/RESEARCHER actor, and exact source/identifier matching; no opaque provider assertion is enough. Merge commands are excluded from PR2-01.

Queries: `get_literature_source(project_id,id)`, `find_source_by_identifier(project_id,type,value)`, `list_source_identifiers(project_id,source_id)`. All require active membership and source–project link; unauthorized lookup returns the same not-found shape as an absent source. Query DTOs disclose source ID and verification status, never another project's links or current SourceVersion. Reads do not mutate.

Ports: `LiteratureSourceRepository` with `get`, `get_for_update`, `add`, `get_by_normalized_identifier`, `has_project_link`, `add_project_link`; `SourceIdentifierRepository` with `get`, `list_for_source`, `add`, `mark_verified`. They return domain models/DTOs, not ORM entities. Application uses the existing synchronous UnitOfWork; persistence alone owns SQLAlchemy. Actor and Project membership/role checks use PR2-00 ports. Human and Agent callers use the same ordinary Application service.

HTTP adapter: `POST /v1/projects/{project_id}/literature/sources`, `POST /v1/projects/{project_id}/literature/sources/{id}/identifiers`, `POST /v1/projects/{project_id}/literature/identifiers/{id}:verify`, `GET /v1/projects/{project_id}/literature/sources/{id}`, `GET /v1/projects/{project_id}/literature/sources:resolve?identifier_type=&identifier_value=`. CLI equivalents: `researchbase literature source create|show|resolve --project-id`, `researchbase literature identifier add|verify|list --project-id`. Both pass authenticated actor context into Application; no route or CLI handler commits directly. API/CLI must return the same normalized DTO and error codes.

Errors: `SOURCE_IDENTITY_CONFLICT` 409, `IDENTIFIER_INVALID` 422, `IDENTIFIER_ALREADY_BOUND` 409, `SOURCE_NOT_FOUND` 404, `IDENTIFIER_BASIS_NOT_FROZEN` 409, `FORBIDDEN` 403, `CONCURRENT_MODIFICATION` 409, `IDEMPOTENCY_CONFLICT` 409. A duplicate request with the same idempotency key and canonical input returns the same IDs; a changed payload conflicts. SQL uniqueness errors map to deterministic Application errors after re-read, not arbitrary 500 responses.
