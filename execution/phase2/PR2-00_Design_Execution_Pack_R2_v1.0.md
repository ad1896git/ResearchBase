The 0019 migration preflights availability of PostgreSQL `btree_gist` for the UUID GiST exclusion and fails closed if unavailable. It also installs a deferred `project_owner_coverage` constraint trigger, an `actors.retired_at` guard trigger and per-project lock protocol. Membership ACTIVE intervals are reconstructed from initial ACTIVE and terminal SUSPENDED/ENDED events; suspended rows never return to ACTIVE. Enrollment starts coverage at DB transaction time; no historic backfill. At commit, every enrolled project has an effective OWNER now and contiguous interval union from its enrollment instant to infinity, considering ACTIVE membership and active subject binding. Finite OWNER intervals require a touching/overlapping successor chain ending with an unbounded assignment. Closing membership/role, actor retirement or binding revocation uses sorted project locks and cannot create a gap. Direct SQL violating coverage is rejected. Enrolled project marker is the immutable initial membership event with typed event_kind `PROJECT_ENROLLMENT` or `FIRST_BOOTSTRAP`; `ownership_started_at` is that event's DB timestamp, and no new project column is added. Project `created_by` remains unchanged.

The source of truth for initial ownership is the initial membership + role + events. A bootstrap record certifies the first ceremony; it does not substitute for membership. Every new Phase 2 project uses `create_project_with_owner`; no OWNER-free intermediate commit. Reactivation creates new membership/role rows and events, never reopens old intervals. All lifecycle records remain queryable after archive.

## Commands, adapters and deterministic errors

Application commands, each one SERIALIZABLE transaction: `bootstrap_first_owner(BootstrapAuthority, request_id, display_name, project_name)`, `bind_legacy_actor_subject(VerifiedPrincipal, operator_attestation, actor_id, request_id)`, `provision_actor(owner_context, VerifiedPrincipal, operator_attestation, request_id)`, `revoke_actor_subject_binding`, `create_project_with_owner`, `enroll_legacy_project_owner`, `assign_project_role`, `close_project_role`, `suspend_project_membership`, `end_project_membership`, `reactivate_project_membership`. The trusted adapter constructs authority/proof; caller text cannot. Bootstrap accepts only host CLI, checks empty actors/projects under deployment lock, and records the exact normalized fingerprint in R2 contract 16. The one-use secret's bytes never enter DB/log/artifact and its authority expires after successful commit. Every later bootstrap invocation, including the same request UUID/payload, returns `BOOTSTRAP_CLOSED` without mutation; an operator audit query can retrieve the original record. Concurrent first bootstrap yields exactly one record. `bind_legacy_actor_subject` requires a deployment-operator signed, immutable content-addressed onboarding record explicitly tying actor UUID to the normalized subject, deployment, operator/subject credential IDs, fresh challenge digest, evidence source and UTC time. The subject answers the challenge through kernel-verified OS peer identity or mTLS private-key handshake. The record bytes must be retained in the protected local deployment audit store before commit; its hash and content address populate `proof_sha256`/`proof_record_ref`. Missing signature, expired challenge, no actor-specific evidence or absent audit bytes returns `SUBJECT_BINDING_UNPROVEN`; display name, historic `created_by` and headers cannot establish the link. New provisioning creates an unroled actor. All other commands require an authenticated actor mapped via active binding, active membership, effective role and project owner guard. HTTP writes have mTLS verified-principal adapter; CLI uses kernel UID. No HTTP bootstrap or caller-supplied actor authority.

Named errors: `AUTHENTICATION_REQUIRED` 401; `FORBIDDEN` 403; `SUBJECT_BINDING_UNPROVEN` 403; `SUBJECT_ALREADY_BOUND`, `OWNER_COVERAGE_GAP`, `BOOTSTRAP_CLOSED`, `IDEMPOTENCY_CONFLICT`, `CONCURRENT_MODIFICATION` 409; malformed subject/proof/request 422. Authorization does not leak whether another actor/project exists. Operator proof metadata is available only through operator audit query.
