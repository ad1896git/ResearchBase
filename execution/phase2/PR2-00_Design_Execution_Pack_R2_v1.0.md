## Goal, order and exclusion

This PR precedes PR2-01; PR2-01 requires accepted PR2-00 implementation, evidence and independent review and is not authorized by this pack. The proposed 0019 migration preflights availability of PostgreSQL `btree_gist` for the UUID GiST exclusion and fails closed if unavailable. It also installs a deferred `project_owner_coverage` constraint trigger, an `actors.retired_at` guard trigger, challenge/binding consistency guards and the per-project lock protocol. Membership ACTIVE intervals are reconstructed from initial ACTIVE and terminal SUSPENDED/ENDED events; suspended rows never return to ACTIVE. Enrollment starts structural coverage at its DB event timestamp; no historic backfill. At commit, every enrolled project has contiguous structural OWNER role/membership coverage from its enrollment instant to infinity, considering retirement and binding revocation known to the database. Finite OWNER intervals require a touching/overlapping successor chain ending with an unbounded assignment. Closing membership/role, actor retirement or binding revocation uses sorted project locks and cannot create a structural gap. Direct SQL violating coverage is rejected. Operational `effective_owner(actor,project,t)` additionally requires a live trusted credential at fresh authorization time; external credential expiry can make it false without a database mutation. A role interval is never rewritten to conceal that fact. Enrolled project marker is the immutable initial membership event with typed event_kind `PROJECT_ENROLLMENT` or `FIRST_BOOTSTRAP`; `ownership_started_at` is that event's DB timestamp, and no new project column is added. Project `created_by` remains unchanged.

The source of truth for initial ownership is the initial membership + role + events. A bootstrap record certifies the first ceremony; it does not substitute for membership. Every new Phase 2 project uses `create_project_with_owner`; no OWNER-free intermediate commit. Reactivation creates new membership/role rows and events, never reopens old intervals. All lifecycle records remain queryable after archive.

## Commands, adapters and deterministic errors

Application commands, each one SERIALIZABLE transaction: `bootstrap_first_owner(BootstrapAuthority, request_id, display_name, project_name)`, trusted challenge issuance for a named eligible legacy actor, `bind_legacy_actor_subject(VerifiedPrincipal, challenge_id, live_response, operator_attestation, actor_id, request_id)`, `provision_actor(owner_context, VerifiedPrincipal, operator_attestation, request_id)`, `revoke_actor_subject_binding`, `create_project_with_owner`, `enroll_legacy_project_owner`, `assign_project_role`, `close_project_role`, `suspend_project_membership`, `end_project_membership`, `reactivate_project_membership`. The trusted adapter creates a fresh unpredictable nonce and constructs authority/proof; caller text cannot. The Application persists its digest and exact actor/deployment/subject/credential/operator tuple before delivery. The signed immutable onboarding attestation names challenge ID and digest plus actor-specific contemporary evidence; its protected content-addressed audit bytes must exist before binding commit. The subject answers through kernel-verified OS peer identity or mTLS private-key handshake. Display name, historic `created_by`, headers, missing signature/audit bytes and a later verification event are insufficient. Bootstrap remains the separate one-use host-CLI ceremony with the R2 normalized fingerprint; later attempts return `BOOTSTRAP_CLOSED`. New provisioning creates an unroled actor and does not consume a legacy challenge.

For `bind_legacy_actor_subject`, take the deployment lock, challenge row lock and every other blocking lock required for the binding. Reread challenge, actor and subject state; verify `status=ISSUED`, exact attestation/principal tuple, independent operator and live subject proof. Fetch a **fresh** PostgreSQL `clock_timestamp()` only after those locks. Require `issued_at <= t < expires_at` and live operator/subject credentials valid at `t`. In one transaction, mark C CONSUMED with its result binding ID and create the binding and LEGACY_BOUND event; deferred FKs/triggers validate the complete cycle at commit. Rollback leaves neither binding nor consumption. Concurrent attempts on C permit at most one committed binding. Revocation changes only the binding/event state and never reopens C. At/after expiry return `ENROLLMENT_CHALLENGE_EXPIRED`, whether or not a sweeper marked EXPIRED. Missing/mismatched proof returns `SUBJECT_BINDING_UNPROVEN`. A new enrollment ceremony requires a new challenge.

**TEMP-AUTH-01 applies to every PR2-00 first-time protected action.** Required order: normalize request → acquire all blocking locks required for its effect → reread locked durable state → obtain fresh advancing DB time using `clock_timestamp()` → evaluate every expiry-sensitive predicate at that same time, including actual credential validity, role/membership interval, challenge and operator authority where applicable → effect and durable event/result → commit. `CURRENT_TIMESTAMP`, `now()`, `transaction_timestamp()` and a timestamp sampled before a lock wait cannot be the final expiry-sensitive authorization time. If a further required blocking wait occurs after final authorization, reread affected state, obtain another `clock_timestamp()` and recheck before mutation; a serialization retry repeats the full sequence. The `effective_owner(actor,project,t)` operational check is `role_binding_valid(actor,project,t) AND credential_valid(actor,t)` at this fresh post-lock `t`. An open role does not preserve an expired credential; no database update or historical role rewrite is required for expiry to deny authority. HTTP writes have an mTLS verified-principal adapter; CLI uses kernel UID. No HTTP bootstrap or caller-supplied actor authority.

**Governance boundary:** PR2-00 implements project membership/role and challenge/credential checks, which are prerequisites for later governance. It does not create ApprovalGrant, consume grants, return grant-consumption receipts or implement R4's governance grant cross-expiry test. The separately authorized governance PR owns those first-time grant effects and the A21 current-read-entitlement rule for exact completed `ApprovalGrantConsumption` receipt disclosure. PR2-01 owns only its literature receipt replay policy under R2 contract 16 and remains blocked until PR2-00 acceptance.

Named errors: `AUTHENTICATION_REQUIRED` 401; `FORBIDDEN` and `SUBJECT_BINDING_UNPROVEN` 403; `SUBJECT_ALREADY_BOUND`, `OWNER_COVERAGE_GAP`, `OWNER_CREDENTIAL_UNAVAILABLE`, `ENROLLMENT_CHALLENGE_EXPIRED`, `BOOTSTRAP_CLOSED`, `IDEMPOTENCY_CONFLICT`, `CONCURRENT_MODIFICATION` 409; malformed subject/proof/request 422. Authorization does not leak whether another actor/project exists. Operator proof metadata is available only through operator audit query. These names do not change the frozen R2/R3 rules for unrelated errors.
