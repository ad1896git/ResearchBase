## Exact migration `0020_literature_source_identity`

Descend from accepted `0019_phase2_bootstrap_membership`. Add **only five** tables below plus constraints, indexes and local immutability/state triggers. UUIDs Application-supplied, times `TIMESTAMPTZ`, all FKs RESTRICT, persisted enums UPPER_SNAKE_CASE. `source_kind` and registration title are public metadata. Normalization version is stored per identifier to preserve meaning across later changes. No schema uses polymorphic target ID/JSON as canonical identity.

`source_identifiers` has one active normalized value globally even across projects; a REJECTED row remains historical and no longer occupies the active unique slot. Database constraints plus advisory lock on `(identifier_type,normalized_value)` serialize correction/rebinding. Registration of a link and rejection both lock the source ID before link-count/authority checks, so a concurrent second-project link cannot race through the sole-project rejection rule. A source with no primary is valid after rejection. The prior `is_primary` bit on a rejected row remains historical; this PR has no primary-selection command. Every basis ArtifactVersion must be FROZEN at command time; a DB trigger/locked check protects against direct write. No scientific delete cascade.

## Normalization, state and access

Implement the exact `source-identifier-normalization-v1` table in R2 contract 16 as a pure typed function; pin the IDNA profile there (UTS #46 nontransitional, STD3, NFC, IDNA2008), RFC 3986 URL behavior, DOI percent rules and modern/legacy arXiv work-ID/version-hint rules. Version hints are returned only as noncanonical input metadata, never stored as SourceVersion. Table-driven vectors cover case, NFC, escapes, invalid UTF-8/IDNA, duplicate URL equivalence, arXiv wrappers, malformed year/month/version, DOI encoded slash and all other types. A future algorithm change gets a new version and migration/compatibility review, not silent renormalization of existing rows.

Commands use one synchronous Application/UoW transaction, and accept `VerifiedPrincipal` resolved by PR2-00 plus explicitly supplied project. OWNER/RESEARCHER may register/add/verify; rejection requires an authenticated HUMAN OWNER under the sole-linked-project rule. Other active roles may query linked sources. A registration with an existing VERIFIED identifier may link that source to the caller project only if kind/title input is compatible and caller is authorized; an UNVERIFIED collision, different source kind, different NFC/outer-trim title, or explicit different target returns `SOURCE_IDENTITY_CONFLICT`. Exact kind and normalized title equality is the compatibility rule; title alone never proves identity. An initial identifier is optional; a source without identifier is not deduplicated by title. Adding an identifier to a source requires its project link. Verification requires frozen basis and matching linked source. Rejection requires frozen basis/reason, an authenticated HUMAN OWNER and exactly one project link on the source (the supplied project). A shared source returns `SHARED_SOURCE_REJECTION_REQUIRES_REVIEW` 409 with no mutation; its correction policy belongs to PR2-02. Authorized rejection transitions status in one transaction with the event, clears current verification fields and never rewrites earlier events. Later rebinding uses a **new** add row and separate verify. Queries `get_literature_source`, `find_source_by_identifier`, `list_source_identifiers` require active project membership and link; absence and unauthorized source share `SOURCE_NOT_FOUND` 404. No read exposes other project's links.

Command signatures: `register_literature_source(context,project_id,kind,title,initial_identifier?,request_id)`; `add_source_identifier(context,project_id,source_id,type,value,is_primary,request_id)`; `verify_source_identifier(context,project_id,identifier_id,basis_artifact_version_id,reason,request_id)`; `reject_source_identifier(context,project_id,identifier_id,basis_artifact_version_id,reason,request_id)`. All four use the durable receipt table and the literal canonical input-hash payloads in R2 contract 16. Rejection replay returns the original event ID/DTO after rechecking current HUMAN OWNER and sole-project-link authority. Its event unique `(identifier_id,request_id)` is an additional database backstop.

HTTP routes: `POST /v1/projects/{project_id}/literature/sources`, `POST /v1/projects/{project_id}/literature/sources/{source_id}/identifiers`, `POST /v1/projects/{project_id}/literature/identifiers/{identifier_id}:verify`, `POST /v1/projects/{project_id}/literature/identifiers/{identifier_id}:reject`, and GET source/resolve/identifiers routes. HTTP `Idempotency-Key` must be UUID; absent/invalid is 422. CLI: `researchbase literature source create|show|resolve`, `researchbase literature identifier add|verify|reject|list`, each with `--project-id`; writes require `--request-id UUID`. Both adapters use the same Application command/DTO and verified actor, never direct ORM commits. An `X-Actor-ID` is optional correlation metadata only and must agree with resolved actor.

## Durable idempotency and errors

For each of the four commands, compute `sha256-cjson-v1` over the exact uppercase-typed literal JSON payload in R2 contract 16: register includes `initial_identifier:null` when absent; add includes source ID, type/value/version/primary; verify and reject include identifier ID, frozen basis ID and normalized reason. Exclude request ID and transport headers; scope contains deployment/project/actor/command. Equivalent raw identifier spellings hash identically after normalization. Scope key includes deployment/project/authenticated actor/command/request UUID. Receipt and result rows commit together. Same key+hash replays saved DTO and IDs after current authorization check; same key+different hash returns `IDEMPOTENCY_CONFLICT` 409. Concurrent same key blocks/retries behind PostgreSQL uniqueness and returns one result. Rollback removes both receipt and result. Different keys with same identifier obey partial unique and return a typed identity conflict, not an arbitrary 500. Exact result ID/DTO parity is required for API and CLI replay. Error codes: `IDENTIFIER_INVALID` 422, `SHARED_SOURCE_REJECTION_REQUIRES_REVIEW` 409, `SOURCE_IDENTITY_CONFLICT`/`IDENTIFIER_ALREADY_BOUND`/`IDENTIFIER_BASIS_NOT_FROZEN`/`IDEMPOTENCY_CONFLICT`/`CONCURRENT_MODIFICATION` 409, `SOURCE_NOT_FOUND` 404, `FORBIDDEN` 403, `AUTHENTICATION_REQUIRED` 401. Rejected identifiers are excluded from active resolve; their history is visible only through authorized source history query.
